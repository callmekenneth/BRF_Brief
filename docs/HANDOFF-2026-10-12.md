# BRF Brief – handoff 2026-10-12

## Purpose
The original goal is to migrate the existing BRF Brief workflow to Hermes on DGX Spark, using a local Qwen model. BRF Knowledge is an adjacent shared RAG service, not a substitute for the briefing.

## Intended v1
- Read approved board sources: email, calendar and Trello.
- Identify upcoming meetings, deadlines, pending work and changes since the previous run.
- Produce a concise Swedish briefing with source references and clear uncertainties.
- Store results and run history on the always-on server.
- Suggest actions but require approval for messages or external modifications.
- Preserve board rule: Trello ticket status is changed together at board meetings, not autonomously between them.

## First tasks
1. Describe the current briefing as a Hermes SOP/skill.
2. Connect one read-only source and test its permissions.
3. Produce one local manual briefing and compare with existing output.
4. Add scheduling, change tracking and meeting preparation after validation.

Keep personal credentials isolated from the shared board portal. No personal or board data in this public GitHub repository.
